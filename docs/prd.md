## 1. 背景与问题

用户想玩到一款「游戏发展国（Game Dev Story）」式的游戏开发模拟经营游戏：经营一家小型游戏工作室，立项开发游戏、雇佣培养员工、跟随主机平台世代更替、发行作品、拿评分与年度大奖，用 10 年时间把小作坊做成知名工作室。

现有网页版同类作品普遍是数值点击器：缺少「类型 × 主题」组合的策略乐趣、缺少员工能力影响成品质量的手感、缺少平台世代变化带来的节奏推进。本项目的核心价值是把「立项决策 → 开发过程 → 市场反馈 → 声望成长」这条闭环做扎实，并用复古像素视觉还原那股年代味。

## 2. 产品定位与用户

| 项 | 定义 |
|---|---|
| 产品形态 | 单机网页游戏，浏览器直接打开即可玩，无需登录、无需后端 |
| 目标用户 | 玩过或听说过游戏发展国、喜欢模拟经营与数值成长的玩家；单局 20-60 分钟 |
| 体验目标 | 每次推进一周都有新信息可看；每个项目立项时都要做取舍；第 3 年后能感到「工作室真的变强了」 |
| 视觉基调 | 像素复古风：纯 CSS 手写像素边框、点阵字体感、低分辨率配色（参考 90 年代 PC 游戏 UI），不依赖位图素材 |

## 3. 产品契约

| 要素 | 定义 |
|---|---|
| 触发 | 玩家打开页面，看到自己的工作室与「推进一周」按钮 |
| 核心工作 | 立项（选类型 × 主题 × 平台）→ 分配员工开发 → 发行 → 读评分与销量 →  reinvest 招募/培训/解锁新平台 |
| 完成条件 | 走完 10 年（520 周）进入年终总决算；累计现金为负且无法支付薪水时提前破产结束 |
| 信任原则 | 本地存档是唯一事实源（localStorage）；本仓库文档与代码随 git 版本化 |

## 4. 核心对象（唯一定义）

| 对象 | 定义 |
|---|---|
| 工作室 Studio | 玩家的公司实体：现金、粉丝数、等级（1-5）、口碑、已解锁平台、员工名单、历史作品 |
| 员工 Staff | 可雇佣的角色，含岗位（程序/美术/音效/策划）、四项能力值、薪水、体力、等级 |
| 项目 Project | 一个正在开发或已完成的游戏：类型、主题、平台、开发点数需求/进度、品质加成、营销投入、发行后的销量与评分 |
| 类型 Genre | 游戏类型（RPG/动作/模拟/冒险/益智/竞速…），每个类型有当前热度曲线 |
| 主题 Theme | 游戏题材（幻想/科幻/校园/历史/运动…），与类型存在契合度矩阵，决定品质系数 |
| 平台 Platform | 主机平台，含解锁年份、装机量曲线、授权/开发成本系数、生命周期（会退市） |
| 周 Week | 最小时间单位；每年 52 周，共 520 周 |
| 评分 Score | 0-40 分（创意/画面/音效/耐玩四项各 0-10），决定销量与口碑 |

## 5. 核心旅程

1. **开局**：100 万现金、2 名初始员工（1 程序 + 1 美术）、仅 PC 平台可用、工作室等级 1。
2. **第一年**：立项一个低成本小游戏 → 2 名员工开发 4-8 周 → 发行 → 拿到 20 分上下、卖出十几万份 → 用利润雇第 3 人。
3. **第二至四年**：解锁新平台（掌机/家用主机），品类组合试错，开始做「类型 × 主题」高契合度项目，粉丝数上千。
4. **第五年之后**：员工培训成型（单项能力 8+），能做出 30 分以上的大作，开始冲年度大奖。
5. **第十年结算**：显示工作室总资产、作品数、最高评分、获奖数，给出评级与结语，允许「继续经营（无尽模式）」。

## 6. 功能需求

### FR-1 时间推进与周结算

- 玩家点击「推进一周」推进 1 周；顶部显示「第 N 年 第 W 周」。
- 每周按固定顺序结算：员工体力变化 → 项目开发进度累积 → 项目开发事件 → 收入长尾结算 → 薪水支出 → 平台/市场波动 → 新闻与解锁事件 → 自动存档。
- **年度节奏**：每年第 1 周固定触发「年初事件」（刷新类型热度、播放平台上市/退市预告、竞品大作新闻）；每年第 52 周固定触发「年末事件」（年度大奖评选、年度财务小结、工作室等级结算、平台世代状态更新）。
- 每次推进必须产生可感知变化（进度、日志、新闻至少一项），禁止空转周。
- 破产判定：结算后现金 < 0 且下月薪水无法支付，进入破产结算界面。

### FR-2 立项（类型 × 主题 × 平台）

- 立项弹层依次选择：平台 → 类型 → 主题，实时显示预估成本、预计开发周数、契合度评级。
- 契合度矩阵：类型 × 主题 组合给出系数 0.6 / 0.8 / 1.0 / 1.2 / 1.5（初始值，可调），直接乘入品质计算；高契合组合在立项界面用醒目颜色提示。
- 平台决定开发成本倍率与潜在装机量上限；已退市平台不可再立项。
- 立项消耗一次性企划费用；同一时间只允许 1 个在研项目（初始版本约束，降低复杂度）。

### FR-3 开发过程

- 项目需要「开发点数 DP」，需求值由平台成本系数 × 类型基础值决定。
- 员工每周贡献 DP：贡献 = 岗位主能力 × 体力系数 × 岗位匹配系数；岗位不匹配（如美术去做程序）贡献减半。
- 项目四条品质线（创意/画面/音效/耐玩）分别由策划/美术/音效/程序能力累积贡献，决定最终评分。
- 开发中随机触发事件（每周 8% 概率，事件池见附录 C）：事件写入开发日志，需要玩家在弹层中二选一或确认；不处理则默认走「保守选项」。部分事件（挖角、设备故障）可在事件池中按年份加权，后期更凶。
- 每周开发日志至少输出一条：进度增量、品质增量、事件结果或员工状态变化。
- DP 满后进入「发行准备」：可追加营销预算（0/小/中/大三档，直接加销量系数并扣现金），确认后发行。
- 开发期间不允许修改员工分配以外的立项参数（平台/类型/主题锁定），避免反复重开蹭契合度。

### FR-4 评分与销量

- 评分 = 四条品质线折算（各 0-10，合计 0-40），叠加契合度系数与平台世代修正，最终取整。
- 销量 = 基础销量 × 平台装机量系数 × 评分系数 × 粉丝系数 × 营销系数 × 类型热度系数 × 随机浮动(0.85-1.15)。
- 收入不一次性到账：发行后按 6 周长尾分摊结算，每周显示「本作本周销量/收入」。
- 评分 ≥ 32 时工作室粉丝大幅增长并触发媒体好评事件；评分 ≤ 15 时粉丝流失。

### FR-5 员工系统

- 招聘市场每周刷新 2-3 名候选人（岗位、四项能力、薪水要求随机），雇佣消耗一次性签约金。
- 员工每 4 周结算薪水；现金不足时先扣款失败，触发警告，累计两次破产。
- 体力 0-100：工作每周 -8，休息一周 +40；体力 < 30 时贡献减半，< 10 时必须休息。
- 培训：花钱让员工单项能力 +1（费用随当前能力递增，上限 10）；等级随累计贡献提升，等级提升涨薪。
- 员工数上限由工作室等级决定（1 级 3 人，逐级 +1，最高 8 人）。

### FR-6 平台与市场（世代更替）

- 平台时间线固定剧本（D8），完整表见附录 A：平台有「上市年 / 巅峰年 / 退市年」三个关键年份，每局一致。
- 装机量按平台曲线增长，巅峰期销量系数最高；进入衰退期后每年销量系数 × 0.6；退市后已发行作品销量再 × 0.3，且不可再立项。
- 每年年初固定播放「平台动态」新闻：新平台上市、老平台宣布退市时间、竞品大作发布。
- 新平台上市当年解锁立项资格；在即将退市平台立项时，立项界面必须给出红字警告「该平台将于第 N 年退市」。
- 每年年初刷新「类型热度」：每个类型热度在 0.8-1.3 区间随机游走（±0.15），界面用涨跌箭头提示；新平台上市会把对应类型的短期热度拉高。
- 平台世代修正：同时代最新平台 +5% 品质系数（技术红利），在用旧平台 -5%。
- 每年 2-4 条新闻（新平台上市、竞品大作、行业事件、员工行业新闻），新闻进入右栏新闻流并保留最近 12 条。

### FR-7 年度大奖与成长

- 每年年末评选「年度最佳游戏」：当年发行作品中评分最高者获奖；玩家作品获奖 → 现金奖励 + 粉丝大涨 + 工作室等级进度。
- 工作室等级经验来自累计发行作品评分与销量；升级解锁员工位、更高预算档位、部分平台。
- 第 10 年年末进入总决算界面。

### FR-8 存档

- 自动存档：每次周结算后写入 localStorage（单存档位）。
- 提供「重新开始」按钮，二次确认后清空存档。
- 存档结构带版本号，便于后续兼容处理。

### FR-9 界面布局（桌面横屏 1280×800 起）

- 顶栏：年月周、现金、粉丝、工作室等级/经验、推进一周按钮、存档状态。
- 左栏：员工列表（能力条、体力、薪水、休息/培训按钮）。
- 中栏：工作室主视图（当前项目进度条、四品质线、开发日志流）。
- 右栏：市场面板（当前平台、类型热度、新闻、年度大奖倒计时）。
- 弹层：立项、招聘、培训、事件抉择、发行结算、年度大奖、破产/总决算。

### FR-10 视觉与手感

- 像素复古风：直角边框、双线像素描边、有限色板（深蓝/米黄/橙/绿）、等宽或点阵字体、无圆角无渐变阴影。
- 所有关键操作有即时反馈（按钮按下位移、数值跳动、日志逐条出现）。
- 不使用外部图片素材；图标用 CSS/Unicode 方块绘制。

### 附录 D：核心公式（v1.1 Demo 校准值）

- 单员工周 DP = 主能力(1-10) × **0.7** × 体力系数（≥30 为 1.0，10-29 为 0.5，<10 为 0）× 岗位匹配（1.0，跨岗 0.5）
- 团队协调系数 = max(0.6, 1 - 0.04 × (在研人数 - 1))，对总 DP 与各线贡献同时生效
- 项目 DP 需求 = 类型基础值（60-120）× 平台成本系数 × **（1 + 0.1 × (当前年 - 1)）**
- 品质线 = clamp(该线员工的主能力加权平均 × 契合度系数 × 世代修正（+5% / -5%）+ 事件加成, 0, 10)
- 评分 = 四条品质线取整后相加（0-40）
- 销量（万份）= (评分 / 10)² × 5 × 平台装机系数 × 粉丝系数 × 营销系数 × 热度系数 × 随机(0.85-1.15)
  - 粉丝系数 = 1 + log10(1 + 粉丝数) / **8**
