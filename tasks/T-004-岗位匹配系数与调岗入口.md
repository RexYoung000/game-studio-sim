## 描述

PRD FR-3：「贡献 = 岗位主能力 × 体力系数 × 岗位匹配系数；岗位不匹配（如美术去做程序）贡献减半」，附录 D 公式写的是「岗位匹配（1.0，跨岗 0.5）」。现状是每名员工永远按自身岗位的主能力产出、只喂自己那条品质线，`CROSS_ROLE_FACTOR` 在 `balance.js` 里定义了却从未被引用——「把美术挪去顶程序」这个策略层完全不存在。

范围：`src/state.js`（`project.assignment` 结构）、`src/systems/project.js`（`weeklyDp` / `tickProject` 按指派计算）、`src/systems/sales.js`（品质线归属）、`src/actions.js`（新增 `ASSIGN_STAFF`）、`src/data/staff.js`（岗位↔能力↔品质线映射）、`src/ui/studioPanel.js`（项目卡片调岗下拉）、`src/data/balance.js`（启用 `CROSS_ROLE_FACTOR`）。

## 验收标准

- [ ] 在研项目内可为每名员工指派 程序 / 美术 / 音效 / 策划 四个岗位之一
- [ ] 指派与员工本职岗位一致时系数 1.0；跨岗时系数取 `CROSS_ROLE_FACTOR`（0.5）
- [ ] 员工产出计入「被指派岗位」对应的品质线，`weeklyDp` 与 `tickProject` 数值一致
- [ ] 未指派的员工默认按本职岗位计算，行为与改动前一致
- [ ] 指派随存档保存；项目发行或重新立项后清空
- [ ] `node tests/run.mjs` 全绿，并新增用例覆盖「默认指派 / 跨岗减半 / 品质线归属」
