# 提问规范（questioning）

> 用途：阶段 1（需求/PRD）头脑风暴时 agent 的提问行为规范。事实来源为 `docs/prd.md` FR-1；产出落档要求见 FR-2。

## 逐题提问规则

1. **只问关键决策**：将用户想法拆解为若干**会实质改变产品形态**的关键决策问题（如产品形态、同步方向、技术选型）；细节与实现层问题由 agent 依据仓库约定自行决定，不抛给用户。
2. **逐题提出**：一次只问一题，得到回答后再问下一题；**禁止一次性抛出全部问题**。
3. **环境事实不提问**：agent 能自行查证的环境事实（如工具是否安装、gh 是否登录、目录结构、网络可达性）不提问，直接检查并在对话中汇报结论（例：「gh CLI 已登录 RexYoung000」）。
4. **结论落档**：每题确认后，把决策点、结论与依据写入 PRD「已确认决策记录」章节；未知信息标 `[TBD]`，推断性结论标 `[假设]`，禁止编造数据与业务规则（PRD FR-2）。

## 选项卡渲染规则

- 每题渲染 **2-4 个选项卡**，各选项一句话说明差异与代价；**标注推荐项**并给出一句话理由。
- 用户可任选其一来作答：**点击选项、回复字母（A/B/C/D）、或自由作答**；自由作答优先于预设选项。
- 用户答案不在预设选项内时，照实记录为新结论，不强行归入选项。

渲染示例（表格或列表均可，保留选项字母便于回复）：

> **Q1：Issue 与本地 Task 的同步方向？**
>
> | 选项 | 方案 | 说明 |
> |---|---|---|
> | **A ✅ 推荐** | 单向：本地 → GitHub | 本地为唯一事实源，换 agent 零成本（同 PRD D2） |
> | B | 双向同步 | 需处理双向冲突，复杂度高 |
> | C | 不建 Issue | 失去远端存档与可见性 |
>
> 可点击选项、回复字母，或直接说出你的想法。
